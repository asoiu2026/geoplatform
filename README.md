# gisEngine

`gisEngine` — модульный клиентский движок для построения интерактивных геопорталов и аналитических картографических приложений на основе Leaflet. Проект объединяет базовые подложки, тематические векторные и тепловые слои, механизмы идентификации объектов, полигональный анализ, агрегационные оверлеи и расчёт спектральных индексов Sentinel-2 в рамках единой браузерной архитектуры.

## Общее описание

Архитектура `gisEngine` построена как набор специализированных сервисов, работающих поверх общего состояния приложения. В коде разделены хранение состояния, инициализация карты, загрузка тематических слоёв, стилизация легенд, обработка пользовательского интерфейса и аналитические сценарии, что упрощает расширение и адаптацию движка под предметно-ориентированные геопорталы.

Центральным элементом выступает объект `AppState`, в котором хранятся экземпляр карты, настройки базовых слоёв, метаданные тематических данных, параметры режима идентификации, состояние полигонального анализа, агрегационные результаты и данные сессии Sentinel-анализа. Поверх него работают сервисы, отвечающие за поведение карты, выбор слоёв, управление прозрачностью, интерпретацию легенд, отрисовку векторных и тепловых слоёв, а также аналитические процедуры.

## Основные возможности

- Поддержка нескольких базовых подложек и тайловых источников, включая Google-подобные карты, OSM, рельефные подложки и исторические картографические слои.
- Подключение тематических векторных слоёв из удалённых geobuf/PBF-источников с последующей отрисовкой по набору правил символизации.
- Поддержка тепловых карт для точечных данных с автоматическим построением градиентной легенды.
- Режим идентификации объектов с формированием popup-окна по атрибутам слоя и алиасам полей.
- Режим полигонального анализа на основе пользовательского контура.
- Механизмы агрегационного анализа и картографической визуализации интегральных оценок внутри полигона.
- Расчёт спектральных индексов Sentinel-2 с выбором периода, фильтрацией по облачности, поиском сцен, расчётом индекса и публикацией результата в виде растрового оверлея.
- Вспомогательные UI-компоненты для меню слоёв, переключателей, ползунков прозрачности, аналитических панелей и шаблонов результатов.

## Архитектура

### Основные модули

| Модуль | Назначение |
|---|---|
| `core/AppState.js` | Хранение глобального состояния: карта, реестры слоёв, флаги аналитических режимов, конфигурация легенды, агрегационные параметры и результаты Sentinel-анализа. |
| `gisEngine.js` / `main.js` | Точки входа и сборка приложения из сервисов. |
| `services/MapService.js` | Создание Leaflet-карты, настройка контролов и инициализация feature group для анализа. |
| `services/ThemeLayerService.js` | Загрузка тематических наборов данных, декодирование geobuf, построение векторных и тепловых слоёв, подготовка данных для отображения. |
| `services/LegendStyleService.js` | Определение стиля объектов по правилам легенды и построение содержимого popup-окон. |
| `services/LayerSelectionService.js` | Управление выбором отдельных слоёв и групп слоёв в интерфейсе. |
| `services/OpacityService.js` | Управление прозрачностью тайловых, векторных и тепловых слоёв. |
| `services/PolygonAnalysisService.js` | Обработка режима рисования полигона и запуск анализа по выбранной области. |
| `services/SentinelIndexService.js` | Поиск сцен Sentinel-2, расчёт индексов NDVI, SAVI, NDMI, NDWI, NBR и NDBI, формирование легенды и оверлея результата. |
| `templates/analysisTemplates.js` | HTML-шаблоны для аналитических карточек, метрик, сводок и состояний интерфейса. |
| `ui/MenuRenderer.js`, `ui/bindUiControls.js`, `ui/templates.js` | Отрисовка меню, привязка событий интерфейса и вспомогательные UI-шаблоны. |

### Логика работы

1. Инициализируется общее состояние приложения и создаётся экземпляр Leaflet-карты.
2. Регистрируются базовые подложки, тайловые слои и тематические наборы данных, после чего они выводятся в пользовательское меню.
3. Пользователь управляет отображением слоёв, режимами идентификации, полигонального анализа, прозрачностью и Sentinel-сценариями.
4. Результаты анализа визуализируются в виде popup-окон, карточек, легенд, агрегационных оверлеев и растровых наложений на карту.

## Обзор тематических слоёв

По коду видно, что движок ориентирован на работу с большим набором тематических картографических слоёв, описанных через единый реестр легенды и конфигурацию идентификации. В `identifyConfig` и связанных структурах присутствуют слои геологического, гидрогеологического, почвенного, ландшафтного, ресурсного и прикладного характера, которые могут использоваться как по отдельности, так и в составе агрегационных профилей.

### Основные группы тематических слоёв

| Группа | Примеры слоёв |
|---|---|
| Геологические и геоморфологические | `bedrock`, `quater`, `litology`, `landscape`. |
| Почвенные | `soil`, `soil-resist`. |
| Гидрогеологические | `groundwater`, `waterdepth`, `water-type`, `water-class`, `chclorid`, `chferrum`, `chftorid`, `chsulfat`. |
| Ресурсные и прикладные | `resources`, `resourcesgisrm`, `agro`, `hunt`. |
| Риск- и плотностные | `rodniki-density`, `opolzni-density`. |
| Аналитические и производные | агрегационные профили вроде `wateravailability`, `waterchemistry`, `agro-ecological-potential`. |

### Как устроены тематические слои

Каждый тематический слой описывается через источник данных, атрибут классификации и набор классов легенды, для которых задаются идентификаторы, подписи, цвета и правило сопоставления значениям атрибута. В зависимости от типа слоя используется либо векторная отрисовка по правилам легенды, либо тепловая визуализация с отдельной градиентной легендой.

В коде встречаются как слои прямого отображения пространственных свойств среды, например геологические, почвенные и гидрогеохимические данные, так и производные аналитические слои, в которых значения формируются через процедуры агрегации и скоринга. За счёт этого один и тот же движок поддерживает и просмотр первичных тематических карт, и построение прикладных картографических оценок для задач территориального анализа.

### Тематические слои в аналитике

Тематические слои используются не только для визуализации, но и как входные данные для идентификации, полигонального анализа и расчёта агрегированных профилей. Например, в коде явно заданы профили `wateravailability`, `waterchemistry` и `agro-ecological-potential`, в которых комбинируются показатели по слоям грунтовых вод, глубины залегания, химического состава воды, почв, литологии, агроусловий и плотностных характеристик процессов.

Это означает, что тематические слои в `gisEngine` выступают одновременно как картографическая основа, как источник локальных признаков и как база для интегральных оценок территории. Такой подход делает движок пригодным не только для отображения геоданных, но и для построения проблемно-ориентированных геопорталов с поддержкой анализа и принятия решений.

## Аналитические возможности

### Идентификация и тематический анализ

Движок поддерживает идентификацию объектов по тематическим слоям с выводом атрибутивной информации в popup-окнах. Стиль конкретного объекта определяется на основе правил легенды и значений его атрибутов, что позволяет одному источнику данных соответствовать множеству картографических классов с разной символикой.

### Полигональный анализ и агрегация

Режим полигонального анализа позволяет пользователю нарисовать область интереса и выполнить расчёты внутри выбранного контура. В коде присутствуют механизмы построения квадратной сетки, отбора контрольных точек, вычисления агрегационных оценок, привязки результатов к палитре и визуализации доминирующих значений внутри полигона.

### Индексы Sentinel-2

Сервис Sentinel-анализа поддерживает выбор периода наблюдения, ограничение облачности, поиск сцен через STAC, загрузку спектральных каналов, вспомогательные операции перепроецирования и построение индексных растров. В текущем виде реализованы индексы NDVI, SAVI, NDMI, NDWI, NBR и NDBI, для каждого из которых заданы собственные подписи, цветовые градиенты и параметры легенды.

## Технологический стек

По содержимому кода проект представляет собой браузерное JavaScript-приложение, построенное вокруг Leaflet и сервисно-модульной архитектуры. Также в коде прослеживается использование geobuf/Pbf, кластеризации маркеров, инструментов рисования на карте, heatmap overlay, геометрических операций Turf, чтения GeoTIFF и библиотеки `proj4` для координатных преобразований в Sentinel-сценариях.

## Запуск проекта

В предоставленном дампе кода отсутствуют `package.json`, lock-файлы и явные инструкции по запуску, поэтому точные команды установки и старта нельзя восстановить однозначно только по этому фрагменту. При этом по структуре кода видно, что проект рассчитан на выполнение в браузере и использует удалённые тайловые, векторные и спутниковые источники данных.

Для README на GitHub можно пока использовать нейтральный шаблон раздела запуска:

```bash
# 1. Клонировать репозиторий
# 2. Установить зависимости выбранным в проекте пакетным менеджером
# 3. Запустить локальный dev-сервер или статический сервер
# 4. Открыть приложение в браузере
```

После добавления в репозиторий `package.json` этот раздел стоит заменить на точные команды.

## Настройка и адаптация

Существенная часть конфигурации приложения хранится непосредственно в состоянии и метаописаниях слоёв: базовые карты, URL тайлов, параметры идентификации, описания тематических слоёв, правила легенды, агрегационные профили и параметры Sentinel-анализа. Поэтому адаптация движка под новый регион или новую предметную область, вероятно, сводится прежде всего к замене источников данных, схем легенды, аналитических профилей и настроек слоёв без серьёзной переработки базовых сервисов.

## Возможные сценарии применения

Проект подходит для геопорталов, которые совмещают картографическую визуализацию и пространственный анализ в одном интерфейсе. Наиболее вероятные прикладные сценарии — тематические карты природных ресурсов, геоэкологические и геологические слои, территориальная оценка, анализ пригодности территорий по полигону и поддержка принятия решений с использованием данных дистанционного зондирования.
